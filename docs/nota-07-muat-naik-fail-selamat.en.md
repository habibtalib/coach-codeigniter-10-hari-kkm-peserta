# 07 · Secure File Upload

> Topic notes (cross-day reference) · Canon: [`docs/spesifikasi-sistem.md`](spesifikasi-sistem.md) · Index: [`README.md`](./nota.md)

## Notes objectives

- **List** the main file upload risks according to OWASP and the controls that address them.
- **Write** CI4 validation rules for BR-PAS-02 (`pdf`/`jpg`/`png`, ≤ 2 MB, ≤ 3 files).
- **Use** the `UploadedFile` API to save files under a random name in `writable/uploads/pas/` and record metadata in `pass_documents`.
- **Build** a download route that checks ownership before sending the file.

---

## 1. Why is file upload dangerous?

An upload form lets users **put files on our server**. That is a big privilege. The main risks (OWASP File Upload Cheat Sheet):

| Risk | Example attack | Control in the course |
|--------|-----------------|----------------------|
| Remote code execution (RCE) | Upload `shell.php` to `public/` then open `https://…/uploads/shell.php` | Store in **`writable/`** (outside the web root) |
| Type spoofing | `shell.php` renamed to `surat.pdf` | Check the **content** (`mime_in` uses finfo) + the extension |
| Path traversal / overwrite | File name `../../app/Config/App.php` | **Don't** use the original name; `getRandomName()` |
| Denial of service | A 2 GB file or 500 files | `max_size`, a maximum of 3 files, `php.ini` limits |
| XSS through a file | SVG/HTML containing `<script>` opened in the browser | Allowlist `pdf`,`jpg`,`png` only; `Content-Disposition: attachment` |
| Data leak | A user guesses the URL of someone else's document | Download through a controller + ownership check (BR-PAS-04) |

**Principle:** an **allowlist** (allow what is known to be safe), not a blocklist (block `.php`, `.exe`…) — a blocklist always misses something (`.phtml`, `.phar`, `.php5`).

---

## 2. Rule BR-PAS-02 (SPEC)

- Type: `pdf`, `jpg`, `png` **only**.
- Size: at most **2 MB** per file.
- Count: at most **3** files per application.
- Location: `writable/uploads/pas/`, random name `$file->getRandomName()`.
- The DB (`pass_documents`) stores **the path + metadata only** — not the file content (BLOB).

## 3. HTML form

```php
<?= form_open_multipart('pas/permohonan') ?>   <!-- enctype="multipart/form-data" + automatic CSRF -->
    <div class="mb-3">
        <label for="documents" class="form-label">Dokumen sokongan (PDF/JPG/PNG, maks 2 MB, maks 3 fail)</label>
        <input type="file" class="form-control" id="documents" name="documents[]" multiple
               accept=".pdf,.jpg,.jpeg,.png">
        <?= validation_show_error('documents') ?>
    </div>
    <button class="btn btn-primary">Hantar</button>
<?= form_close() ?>
```

`accept=` only **makes it easier for the user** to pick a file; it does not stop an attacker. All real checks happen on the server.

## 4. Server-side validation

```php
$rules = [
    'documents' => [
        'label' => 'Dokumen sokongan',
        'rules' => 'uploaded[documents]'
            . '|max_size[documents,2048]'                                   // KB → 2 MB
            . '|ext_in[documents,pdf,jpg,png]'
            . '|mime_in[documents,application/pdf,image/jpeg,image/png]',   // from the content (finfo)
    ],
];

if (! $this->validate($rules)) {
    return redirect()->back()->withInput();
}
```

CI4 file rules check **every** file in `documents[]`. There are three things that **the rules don't do**, so we check them ourselves in the Service:

1. **Number of files** (max 3) — there is no built-in rule.
2. **Extension ↔ content consistency** — `guessExtension()` (from the real MIME type) must be on the allowlist.
3. **Files that PHP failed to upload** (e.g. larger than `upload_max_filesize`) — `isValid()`.

> `ext_in` reads the extension from the client's file name; `mime_in` uses `getMimeType()`, which **detects the type from the content** through the PHP `fileinfo` extension. Both are needed. Make sure `fileinfo` is enabled (see [`docs/persediaan.md`](persediaan.md)).

## 5. The `UploadedFile` API — what can be trusted & what can't

| Method | Source | Trust? | Use for |
|--------|--------|----------|-----------|
| `getClientName()` | The user's browser | ❌ | Display only (`original_name`, always `esc()`) |
| `getClientMimeType()` | Header from the browser | ❌ | Don't use it for security decisions |
| `getMimeType()` | `finfo` on the content | ✅ (reasonably) | Type check, store `mime` |
| `guessExtension()` | From the real MIME type | ✅ | Extension of the stored file |
| `getSize()` / `getSizeByUnit('kb')` | Size of the temporary file | ✅ | `size_bytes`, size check |
| `isValid()` | PHP upload status | ✅ | Reject broken/truncated files |
| `getErrorString()` | PHP error message | — | Log / error message |
| `getRandomName()` | Generated by CI4 (time + random + extension) | ✅ | File name on disk |
| `hasMoved()` | Internal status | — | Avoid calling `move()` twice |
| `move($dir, $name)` | — | — | Move out of the temporary folder |

## 6. Saving the file — code in `PassWorkflowService`

```php
<?php

namespace App\Services;

use App\Models\PassDocumentModel;
use CodeIgniter\HTTP\Files\UploadedFile;
use RuntimeException;

// Excerpt — the documents part only. No new class: SPEC §5 says
// this logic stays in PassWorkflowService.
class PassWorkflowService
{
    private const ALLOWED_EXT  = ['pdf', 'jpg', 'png'];
    private const ALLOWED_MIME = ['application/pdf', 'image/jpeg', 'image/png'];
    private const MAX_FILES    = 3;
    private const MAX_BYTES    = 2 * 1024 * 1024;

    /**
     * Called by submit() after the pass_applications record is created.
     *
     * @param list<UploadedFile> $files from $this->request->getFileMultiple('documents')
     */
    private function storeDocuments(int $applicationId, array $files, string $docType = 'sokongan'): void
    {
        // Drop empty slots (file input with no file chosen)
        $files = array_filter($files, static fn (UploadedFile $f) => $f->getError() !== UPLOAD_ERR_NO_FILE);

        if (count($files) > self::MAX_FILES) {
            throw new RuntimeException('Maksimum 3 fail sahaja.');
        }

        $dir = WRITEPATH . 'uploads/pas';      // writable/uploads/pas — NOT public/
        if (! is_dir($dir)) {
            mkdir($dir, 0750, true);
        }

        foreach ($files as $file) {
            if (! $file->isValid()) {
                throw new RuntimeException('Muat naik gagal: ' . $file->getErrorString());
            }

            // Layered check — even though the rules already passed (defence in depth)
            $mime = $file->getMimeType();              // from the content
            $ext  = $file->guessExtension();           // 'jpg' for image/jpeg
            if (! in_array($mime, self::ALLOWED_MIME, true)
                || ! in_array($ext, self::ALLOWED_EXT, true)
                || $file->getSize() > self::MAX_BYTES) {
                throw new RuntimeException('Jenis atau saiz fail tidak dibenarkan.');
            }

            $original = $file->getClientName();        // stored for display ONLY
            $size     = $file->getSize();              // read BEFORE move()
            $newName  = $file->getRandomName();        // e.g. 1727251200_3f2a9c1e7b.pdf

            if (! $file->hasMoved()) {
                $file->move($dir, $newName);
            }

            // Only metadata + a relative path are stored in the DB
            model(PassDocumentModel::class)->insert([
                'application_id' => $applicationId,
                'doc_type'       => $docType,
                'original_name'  => mb_substr($original, 0, 255),
                'stored_path'    => 'uploads/pas/' . $newName,   // relative to WRITEPATH
                'mime'           => $mime,
                'size_bytes'     => $size,
            ]);
        }
    }
}
```

Why is `stored_path` **relative**? If the application moves to another server (`/var/www/…` → `D:\apps\…`), an absolute path in the DB breaks. Join it with `WRITEPATH` when reading.

> **Consistency with transactions:** moving a file to disk is **not** part of the DB transaction. If the `pass_applications` insert fails after the file was moved, the file becomes an orphan. A simple pattern: save the application record first inside a transaction, then the files; if a file fails, `unlink()` the files already moved and roll back.

In the controller:

```php
$files = $this->request->getFileMultiple('documents') ?? [];
service('passWorkflowService')->submit(auth()->id(), $this->validator->getValidated(), $files);
```

## 7. Download through a controller — with an ownership check

Because the files are in `writable/`, the browser **cannot** reach them through a URL. The only way is the route `/pas/permohonan/dokumen/{id}`, which checks permission first.

```php
public function document(int $id)
{
    $doc = model(PassDocumentModel::class)->find($id);
    if ($doc === null) {
        throw PageNotFoundException::forPageNotFound();
    }

    $app  = model(PassApplicationModel::class)->find($doc->application_id);
    $user = auth()->user();

    // BR-PAS-04 — same as show()
    $canViewAll = $user->inGroup('reviewer', 'approver', 'admin');
    if ($app === null || (! $canViewAll && (int) $app->user_id !== (int) auth()->id())) {
        throw PageNotFoundException::forPageNotFound();
    }

    $fullPath = WRITEPATH . $doc->stored_path;
    if (! is_file($fullPath)) {
        throw PageNotFoundException::forPageNotFound();
    }

    // download() → Content-Disposition: attachment (the file is not rendered in a tab)
    return $this->response->download($fullPath, null)->setFileName($doc->original_name);
}
```

## 8. PHP limits (`php.ini`) — the cause of "silent" errors

If a file is over a PHP limit, CI4 never sees it — `$_FILES` is empty or `isValid()` is false.

| Setting | Suggested training value | Why |
|---------|------------------------|--------|
| `upload_max_filesize` | `8M` | > 2 MB so that the CI4 validation message (not a PHP error) is shown |
| `post_max_size` | `16M` | ≥ 3 × file size + form fields; if exceeded, **the whole `$_POST` is empty** (CSRF fails!) |
| `max_file_uploads` | `20` | Default; we enforce the limit of 3 ourselves |
| `extension=fileinfo` | enabled | Needed by `getMimeType()` / `mime_in` |

Check: `php -i | grep -E "upload_max_filesize|post_max_size"`.

## 9. Upload checklist (DoD M2)

- [ ] Files are stored in `writable/uploads/pas/` — nothing in `public/`
- [ ] `ext_in` + `mime_in` + `max_size` in the rules; count ≤ 3 checked in the Service
- [ ] Name on disk = `getRandomName()`; the original name only in `original_name`
- [ ] `pass_documents` stores a relative `stored_path`, `mime`, `size_bytes`
- [ ] Download through a controller with the BR-PAS-04 check (test with `pemohon2`)
- [ ] `original_name` is displayed with `esc()`
- [ ] Boundary case tests: 2.1 MB, `.exe` renamed to `.pdf`, 4 files, no file

## ⚠️ Common mistakes

| Mistake | Result | Fix |
|-----------|--------|----------|
| `move(FCPATH . 'uploads')` (the `public/` folder) | The file can be reached & executed directly through a URL | `move(WRITEPATH . 'uploads/pas', …)` |
| Using `getClientName()` as the name on disk | Path traversal, files overwritten | `getRandomName()` |
| Only `ext_in` without `mime_in` | `.php` renamed to `.pdf` is accepted | Both + `guessExtension()` |
| Trusting `getClientMimeType()` | The header can be forged | `getMimeType()` (finfo) |
| Calling `getSize()` after `move()` / calling `move()` twice | Error / wrong value | Read the metadata first; check `hasMoved()` |
| `post_max_size` too small | Empty `$_POST` → "The action you requested is not allowed" (CSRF) | Raise `post_max_size` |
| Download without an ownership check | IDOR — personal documents leak | BR-PAS-04 check in `document()` |
| Storing files as a BLOB in the DB | The DB bloats, backups are slow | Path in the DB, file in `writable/` |
